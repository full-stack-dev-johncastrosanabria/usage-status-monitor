# v0.2 — Complete panel and first release

Part A of four ("never run out of AI"): A panel for every AI → B jump between AIs → C session center →
D token saving. Each part gets its own spec, plan and release.

## Goal

Ship v0.2: the usage panel on every platform with a native interface, GitHub Copilot as a provider, installers
on GitHub Releases, and a README that sells the project in ten seconds.

Success: a developer on macOS, Windows or Linux downloads one installer from the Releases page, opens it and
sees how much is left in each of their AI subscriptions without configuring anything.

## Scope

In:

1. Native Windows (WPF, .NET 8) and Linux (GTK4) interfaces, merged after review.
2. GitHub Copilot provider.
3. Release workflow that publishes unsigned installers.
4. Launch README.

Out (later parts): jumping between AIs (B); session history, permission-less modes and Copilot models (C);
compaction (D).

## 1. Native interfaces

The macOS SwiftUI app is merged (a2fdb77). The Windows and Linux branches are reviewed against the same
contract before merging:

- Same content and order as `src/usage_monitor/web/panel.html`: header with status, language and Refresh;
  alert row; Claude accounts table; other providers; Claude Code defaults. Compact layout under 620 px.
- Talks only to the local server (`/api/data`, `/api/ping`, POSTs with `X-Usage-Monitor: 1`); starts the
  bundled backend when nothing answers and stops it on quit; `USAGE_MONITOR_PORT` points it elsewhere.
- Strings in en/es/zh, taken from the panel's `I18N` table.
- Starts at login through `usage autostart on`, which already supports the three systems.

Verification: screenshots against the demo server (`USAGE_MONITOR_DEMO=1`) at normal and compact widths, a
build in CI, and a run in the Windows 11 and Kali VMs.

## 2. GitHub Copilot provider

`providers/copilot.py`, following `providers/codex.py`:

- Token, read only and never refreshed: `oauth_token` from `~/.config/github-copilot/apps.json` (or
  `hosts.json`), else `gh auth token`. `%LOCALAPPDATA%\github-copilot` on Windows.
- `GET https://api.github.com/copilot_internal/user` with `Authorization: token <t>`. The endpoint is not
  documented: any other shape becomes a `ProviderError`, shown as the provider's error.
- Parse `quota_snapshots` (`premium_interactions`, `chat`, `completions`): `unlimited` entries are skipped;
  otherwise `used = 100 - percent_remaining`; resets at `quota_reset_date`; plan from `copilot_plan`.
  Premium requests block; chat and completions do not.
- Added to `Snapshot` (`copilot: Usage | str`), `snapshot.collect`, `to_json`, `term.print_snapshot`, the
  alerts for other providers, demo data, the web panel and the three native apps.
- Tests: parsing from canned responses (limited, unlimited, missing fields), token discovery from a temporary
  home, no network.

## 3. Release workflow

`.github/workflows/release.yml`, on tags `v*`:

| Job | Runner | Output |
|---|---|---|
| macOS | `macos-15` (arm64) and `macos-13` (x86_64) | `UsageMonitor-<v>-<arch>.dmg` via `scripts/package-macos.sh` |
| Windows | `windows-latest` | `UsageMonitor-<v>-win-x64.zip` (app + PyInstaller backend) |
| Linux | `ubuntu-24.04` | `usage-monitor_<v>_amd64.deb` (GTK app + backend) |

The last job creates the release with all files and SHA-256 sums. Tags with `-rc` are marked pre-release.
Nothing is signed; the README keeps the warning and explains how to open an unsigned app on each system.

## 4. Launch README

- One line: "Never run out of AI." Then a 10-second GIF: panel → account at 95% → automatic switch → session
  reopens on the new account. Recorded from demo data only.
- Screenshots of the three apps (demo data).
- Install: one line per system (Releases download, `uv tool install`, `.deb`).
- What it reads and where it sends it (credentials only go to their own provider; nothing is refreshed).
- A short comparison with doing it by hand (checking each website, `/usage` in each tool).

## Release steps

1. CI green on the three systems.
2. Tag `v0.2.0-rc1`; install each artifact in the macOS host (demo port), Windows 11 VM and Kali VM.
3. Fix what breaks, tag `v0.2.0`.

## Risks

- The Copilot and Claude usage endpoints are unofficial and can change: errors stay per provider.
- Unsigned apps trigger Gatekeeper/SmartScreen warnings: documented, signing postponed by the owner.
- Subagent rate limits: native interfaces are resumed, not restarted.
